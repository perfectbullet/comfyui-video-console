# 前端构建与部署命令速查（本地 → 231）

> 本文是 `comfyui-video-console/`（Vue3 + Vite 前端）从本地源码到线上生效的**标准发布流程**速查。
> 适用场景：本地改了 `src/` 下任何代码后，把新版本推到 `192.168.8.231:8600`。
> 完整背景与架构说明见同目录《前端Web控制台部署与运维.md》。
> 最后更新：2026-08-27

---

## 流程总览

```text
本地改代码 → ⓪ git commit → ① npm run build → ② rsync 同步源码 → ③ 231 上 docker compose 重建 vue-web → ④ 验证
```

| 步骤 | 在哪执行 | 耗时 | 影响 |
|---|---|---|---|
| ⓪ 提交 | 本地 `comfyui-video-console/`（Git 仓库） | ~1s | 无 |
| ① 构建 | 本地 `/home/zj/aigc/comfyui-video-console/` | ~0.5s | 仅本地 `dist/` |
| ② 同步 | 本地 | ~1s | 仅服务器 `web/` 源码目录 |
| ③ 重建 | 231 服务器 | 15s–2min | **只重启 vue-web，不动 comfyui-h3** |
| ④ 验证 | 本地 curl | ~5s | 无 |

> 前端是纯静态托管 + 浏览器直调 ComfyUI API，**不占 GPU**；整个流程不会打断推理任务。

## ⓪ 提交 Git（推荐）

```bash
cd /home/zj/aigc/comfyui-video-console
git add -A && git commit -m "改动说明"
```

- `comfyui-video-console/` 是独立 Git 仓库（初始提交 `1a251b9`），每次发布前提交，方便 `git diff`/`git log` 回溯
- `git status` 可查看未提交改动

## ① 本地构建

```bash
cd /home/zj/aigc/comfyui-video-console
npm run build
```

- Vite 打包，产物输出到 `web/dist/`
- 成功标志：输出 `✓ built in xxxms`，并打印 `dist/assets/index-<哈希>.js`
- **记下这个哈希文件名**，第 ④ 步要用它确认线上已生效（源码一变哈希就变，是判断"新版本真的上线了"的依据）

## ② 同步源码到 231

```bash
rsync -az --delete \
  --exclude 'node_modules' --exclude '.vite' --exclude '*.log' --exclude '.DS_Store' \
  /home/zj/aigc/comfyui-video-console/ \
  zenking@192.168.8.231:/data/aigc/comfyui-h3/web/
```

**参数说明：**

| 参数 | 作用 |
|---|---|
| `-a` | 归档模式：递归 + 保留权限/时间戳（增量判断依据） |
| `-z` | 传输时压缩 |
| `--delete` | 镜像同步：删除服务器上本地已不存在的文件，保持两边一致 |
| `--exclude` | `node_modules`/`.vite` 会在容器内重新生成，传过去是浪费；`*.log`/`.DS_Store` 是垃圾文件 |
| 源路径末尾的 `/` | `web/` → `web/` 同步的是**目录内容**；漏写 `/` 会变成把 web 整个塞进对方的 `web/web/` 里 |

**注意事项：**

- SSH 已配免密，无需输密码
- `--delete` 会删掉服务器端手动改过的文件 —— 前端源码请只改本地这份，以本地为准
- 不放心时先加 `--dry-run` 预览将传输/删除的文件清单，确认后再真跑

## ③ 服务器上重建并重启前端

```bash
ssh zenking@192.168.8.231 "cd /data/aigc/comfyui-h3 && docker compose up -d --build vue-web"
```

- `--build`：强制用刚同步的源码重建镜像（多阶段 Dockerfile：容器内 `npm install` + `vite build`，再用 `serve` 托管 `dist/`）
- **只指定 `vue-web`**：`comfyui-h3` 推理容器不会被重建/重启（它是依赖项，保持 Running 原样），不影响 GPU 任务
- `-d`：后台运行

## ④ 验证

```bash
# ① 容器状态：vue-web 应为 Up，comfyui-h3 不受影响
ssh zenking@192.168.8.231 "docker ps --format 'table {{.Names}}\t{{.Status}}' | grep comfyui"

# ② 页面可访问
curl -s -o /dev/null -w "HTTP %{http_code}\n" "http://192.168.8.231:8600/?mode=nine-images"

# ③ 确认线上托管的是新产物：输出的哈希应与第 ① 步本地构建的文件名一致
curl -s "http://192.168.8.231:8600/" | grep -oE "index-[A-Za-z0-9_-]+\.js"
```

**预期结果：**

1. `comfyui-minimax-h3-web Up x seconds`（刚重启）+ `comfyui-h3 Up x hours`（时长很久，证明没被动过）
2. `HTTP 200`
3. **哈希与本地构建一致 = 新版本已生效**；不一致说明构建/同步/重建某一步没成功

## 一步到位版（熟练后使用）

```bash
cd /home/zj/aigc/comfyui-video-console && git add -A && git commit -m "更新" && npm run build && \
rsync -az --delete \
  --exclude 'node_modules' --exclude '.vite' --exclude '*.log' --exclude '.DS_Store' \
  ./ zenking@192.168.8.231:/data/aigc/comfyui-h3/web/ && \
ssh zenking@192.168.8.231 "cd /data/aigc/comfyui-h3 && docker compose up -d --build vue-web" && \
sleep 3 && curl -s "http://192.168.8.231:8600/" | grep -oE "index-[A-Za-z0-9_-]+\.js"
```

最后输出的哈希与本地 `ls dist/assets/` 对得上，即部署成功。

## 常见坑

1. **浏览器缓存**：部署后页面还是旧的 → 强刷（Ctrl+F5）。JS/CSS 是哈希文件名不会缓存错，但 `index.html` 本身可能被浏览器缓存。
2. **改了代码没 build**：rsync 同步的是 `src/`，线上产物由容器内构建，但本地不 build 就无法用第 ① 步的哈希做核对；且 `.dockerignore` 排除了本地 `dist/`（容器内自己构建）。
3. **误重启 comfyui-h3**：只要命令写的是 `up -d --build vue-web`（带服务名）就不会发生；写成不带服务名的 `up -d --build` 会同时处理两个服务，GPU 上正在跑的任务会被打断。
4. **`docker restart comfyui-h3` 曾出现卡死**：NFS 挂载下 kill 后收不到 exit event（exit code 137）。遇到时需要手动处理（如 `docker rm -f` 后重新 `up -d`），或直接在服务器上人工介入。
